# 砚团 · 一起看（主动收音测试版）

这是一条**用户主动开启**的 Android 播放声音 → 临时服务器片段 → MCP 台词识别通道，用于和陪伴者一起理解视频剧情。现阶段一次录 **12 秒**，不提供持续监听、后台偷录、麦克风兜底，也不改变原有截图或读屏功能。

## 使用步骤

1. Android 10 或更高版本，在砚团的「陪伴」页「看见」卡片下点击 **一起看 · 听12秒**。
2. 首次允许 Android 录音权限，并且**每次**确认 Android 的屏幕声音捕获授权。录音时有前台通知，可点「立即停止」。
3. 切回正在播放的视频。录制结束后，砚团把最多 12 秒的 PCM 16 kHz 单声道 WAV 上传到已配置的砚团 server。手机调试日志会记录上传是否成功。
4. 在 MCP 部署环境中设置 **OPENAI_API_KEY**（使用者自行配置，千万不要写进仓库）。确认重新部署 **server 和 mcp** 两个服务；单装 APK 不会更新后端。
5. 在聊天里让陪伴者调用 `listen_together_transcribe`，读取最近一次主动授权录制的片段，取得对白文字，再配合 `peek_screen` 截图讲解剧情。

## 隐私及能力范围

- **只有手机端点击按钮并经过系统授权才能开始**。远程 MCP 不提供启动录音工具，也不触发系统授权窗口。
- 本次声音在服务端只保留于内存，并在 **180 秒**后失效；每个设备新片段覆盖旧片段，不写 WAV 文件。服务器重启也会清空。
- 发送到转写模型时，音频会传给配置的第三方转写服务。请勿录取不愿上传的内容。
- 使用 Android `AudioPlaybackCapture` 捕获 **应用播放的声音**。Android 10 以下不可用；一些视频/流媒体 App 或带 DRM 的音频明确禁止被其他 App 捕获，这种情况下会返回静音，不应声称听到了对白。
- 如果 MCP 未配置 `OPENAI_API_KEY`，只可完成播放声音的授权捕获与临时上传，自动识别暂不可用。
- 当前仅支持**录制后**转写，不是低延迟实时通话，也不能保证和截图的时间戳完全同步。下一阶段可按「录音段落时间戳 ↔ 截图 ↔ 剧情摘要」扩展。

CI 的 Android Debug APK 工作流运行 `server/tests/test_audio_clip.py`、`python -m py_compile server/linjian_server.py`、`node --check mcp/server.js`，以及 Android 构建。
